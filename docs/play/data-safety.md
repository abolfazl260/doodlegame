# Google Play Data Safety inventory

This document is the human-readable privacy/data inventory for DoodleGame. It must describe the code that is actually shipped. The machine-readable companion is `docs/play/privacy-baseline.json`, enforced by CI.

Public Privacy Policy:

https://abolfazl260.github.io/doodlegame/privacy.html

## Current Play Data Safety position

For the current codebase, DoodleGame does **not collect or share Google Play user-data types**.

Google Play defines collection as transmitting user data off the user's device. Data that stays only on the device does not count as collected for the Data Safety form. The current game has no account system, analytics, advertising, crash-reporting SDK, cloud save, telemetry endpoint, push notifications, location feature, contacts access, camera access, or microphone access.

The Play Console Data Safety form must still be completed, and the public Privacy Policy URL must still be supplied even when no user data is collected or shared.

## Local-only state

## Android release permissions

Expected merged release permissions:

- `android.permission.INTERNET`
- `com.abolfazl.doodlegame.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`

`INTERNET` is included by the Capacitor Android WebView runtime. The current DoodleGame code does not send gameplay, identity, advertising, analytics, location, contacts, camera, microphone, or other user data to a DoodleGame backend.

`DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` is generated by AndroidX Core and protected at signature level. AndroidX uses it to preserve the security semantics of dynamically registered `RECEIVER_NOT_EXPORTED` receivers on Android versions where the newer platform flags are not available. It does not grant access to user data and does not represent DoodleGame data collection or sharing.

A permission by itself is not declared as collection in Data Safety unless the app actually collects/shares the corresponding data. CI nevertheless audits the **merged release manifest**, including permissions contributed by dependencies.

Expected sensitive/review-required permissions: **none**.

In particular, the release must not silently add:

- `com.google.android.gms.permission.AD_ID`
- `android.permission.ACCESS_FINE_LOCATION`
- `android.permission.ACCESS_COARSE_LOCATION`
- `android.permission.READ_CONTACTS`
- `android.permission.WRITE_CONTACTS`
- `android.permission.CAMERA`
- `android.permission.RECORD_AUDIO`
- `android.permission.READ_PHONE_STATE`
- media/storage permissions
- notification permission

Any intentional addition requires privacy review and an explicit baseline/documentation update before merge.

## Development-only dependencies

TypeScript, Vite, Capacitor CLI and type packages are build/development tooling. They are not runtime SDKs shipped as user-data collection services. Changes to runtime `dependencies` are blocked by the privacy audit until this inventory and the baseline are reviewed.

## CI privacy guardrail

Run after generating/building the Android release:

```bash
npm run android:audit:privacy
```

The audit:

1. reads the final **merged release AndroidManifest**
2. inventories all `uses-permission` declarations
3. blocks sensitive/review-required permissions unless explicitly allowlisted
4. compares runtime `package.json` dependencies with `privacy-baseline.json`
5. requires all expected permissions and runtime dependencies to appear in this document
6. validates that the public policy file and URL are present
7. writes JSON/Markdown evidence under `artifacts/privacy-audit/`

This is intentionally strict. A dependency upgrade or new permission requires an explicit privacy review instead of silently changing the Play Data Safety answer.

## Update procedure

Before merging any change that modifies runtime dependencies, Android permissions, analytics, advertising, accounts, cloud storage, network APIs, identifiers, or personal/sensitive-data access:

1. determine the new data access/collection/sharing behavior
2. update this document
3. update `docs/play/privacy-baseline.json`
4. update `public/privacy.html` and in-app policy copy when user-facing practices change
5. update the Play Console Data Safety form before releasing the affected artifact
